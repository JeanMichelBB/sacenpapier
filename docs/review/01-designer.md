| ID | Sev | Area | Problem | Evidence | Fix | Effort |
|---|---|---|---|---|---|---|
| D1 | P1 | Cookie banner | Fixed bottom cookie-consent banner overlaps page content/code blocks while reading — `body.has-cookie-banner` only adds `padding-bottom: 96px` inside `@media (max-width: 640px)`, so desktop gets zero reserved space, and even on mobile the banner still covers whatever is scrolled into the last ~96px of the viewport mid-scroll (padding only protects the true end of the document). | `src/app/globals.css:50-55`; `src/components/CookieBanner.tsx:27` (`fixed inset-x-0 bottom-0`); visible overlapping body text/cards in `home-en-light-desktop.png`, `infrastructure-en-light-desktop.png`, `documentation-en-light-mobile.png`, `postmortems-*-desktop.png` | Reserve layout space site-wide (not mobile-only), or convert to a non-overlapping corner toast with enough contrast/backdrop that overlapped text is still legible | M |
| D2 | P1 | Nav/header consistency | Postmortem detail page template has no language toggle, no theme toggle, and no GitHub/LinkedIn/email icons — only a back link — while every other page (home, infrastructure, documentation, postmortems list, about) renders the full icon/toggle set. | `postmortem-detail-dark-mobile.png` / `postmortem-detail-dark-desktop.png` are the only 2 of 8 EN/FR×light/dark×mobile/desktop combos that exist for this template (confirmed via baseline §3 `read_page`); `src/app/postmortems/[slug]/page.tsx:5,51` imports/renders only `<BackLink />`, vs. e.g. `documentation-en-light-desktop.png` which shows Github/LinkedIn/email/FR/theme icons | Add the same header controls (`LanguageToggle`, `ThemeToggle`, social links) used on other templates | S–M |
| D3 | P2 | Nav labels | Two separate top-level tabs both read as "documentation" to a first-time visitor: `homelabDocsNav` = "Documentation" (→ `/documentation`, homelab infra docs) and `docsNav` = "Postmortems/Documentation" (→ `/postmortems`, the blog index of postmortems+updates). Labels don't disambiguate which tab holds which content. | `src/lib/strings.ts:13-14` (EN), `:72-73` (FR); both pills rendered adjacently in `src/components/Hub.tsx:554-581`; visible side-by-side in `home-en-light-desktop.png` | Rename one tab, e.g. "Homelab" vs. "Writing"/"Blog" | S |
| D4 | P2 | Nav labels | First nav tab is labeled "Full-stack" (a role descriptor) while every sibling tab is a content noun (Infrastructure, Documentation, About) — breaks the tab-naming convention and reads oddly as the active/orange pill. | `src/lib/strings.ts:27` (`roleFullStack: "Full-stack"`) used at `src/components/Hub.tsx:538`; shown active in `home-en-light-desktop.png` | Rename to "Projects" to match the noun pattern | S |
| D5 | P2 | Type scale | `text-xs` (and arbitrary `text-[11px]`) is overused for primary UI chrome — nav pills, stat labels, footer, card metadata, even portions of body copy — collapsing most of the UI into the smallest size in the scale. Correlates with axe-core's "serious" `color-contrast` violations firing on 44-88 nodes per page (baseline §2), consistent with small light-gray (`zinc-400/500`) text being the likely driver. | `grep -c text-xs`: `src/components/Hub.tsx` 20×, `InfrastructureContent.tsx` 13×, `HomelabDocsContent.tsx` 8×, `PostListPage.tsx` 7×; additional `text-[11px]` at `Hub.tsx:252,269,283,298,454` | Introduce an actual type scale — reserve `text-xs` for true metadata (timestamps), bump filter pills/stat labels to `text-sm`; re-run axe-core afterward to confirm contrast improves | M |
| D6 | P2 | Homepage iframe UX | The live-project iframe preview cache-busts with `_t=${Date.now()}` on every mount, so it can never be served from HTTP cache — the full cost is paid on every page load, not just the first. No loading skeleton/placeholder is shown while the iframe boots. This is the primary driver of baseline's mobile homepage LCP of 6.7s vs. 2.1-2.7s on every other page (00-baseline.md §2, §4). | `src/components/ProjectPreview.tsx:101-104` (cache-bust effect), `:120-137` (`ScaledFrame`, no loading state) | Only cache-bust on an explicit "refresh" action, not every mount; add a loading placeholder/skeleton so the pane isn't blank during the iframe's own boot | M |
| D7 | P2 | Discoverability | On `/documentation` mobile, the sidebar-reveal toggle is pinned flush to the viewport edge (`left: 0`) when collapsed, rendering as a near-invisible unlabeled sliver. | `src/components/HomelabDocsContent.tsx:213-222` (`left: isMobile ? (sidebarOpen ? 256 : 0) : ...`); visible as a thin "›" shard at the extreme left edge in `documentation-en-light-mobile.png` | Inset a few px so the full chevron affordance is visible, or add an `aria-label`-backed larger hit target with a visible background | S |
| D8 | P3 | Consistency | Pagination size differs for the same content between entry points: the dedicated `/postmortems` and `/updates` pages show 10 items/page, but the same posts embedded in the homepage's docs tab show 6/page. | `src/components/PostListPage.tsx:15` (`PER_PAGE = 10`) vs. `src/components/Hub.tsx:190` (`DOCS_PER_PAGE = 6`) | Use one shared page-size constant | S |
| D9 | P3 | Naming | Page title renders "Post-mortems" (hyphenated) while the nav tab and internal strings key use "Postmortems" (no hyphen) — small but visible mismatch between in-page heading and nav label. | `postmortems-en-light-desktop.png` heading vs. `src/lib/strings.ts` `postmortems:`/`docsNav` values and `Hub.tsx` tab label | Pick one spelling and use it everywhere (code, nav, and visible heading) | S |
| D10 | P3 | Visual hierarchy | `/documentation` has the lowest Lighthouse Accessibility score in the set (86 mobile / 91 desktop vs. 95-96 elsewhere) and uniquely fires axe's `link-in-text-block` (serious, 45 nodes) — inline links in the homelab-doc body copy (e.g. "Tailscale", "SSH") are only distinguished from surrounding paragraph text by color, not weight/underline. | `00-baseline.md` §2; inline orange links visible in running body text in `documentation-en-light-desktop.png` | Add an underline (or weight change) to inline links so they're distinguishable without relying on color alone | S |

Both languages/themes were spot-checked across home, infrastructure, documentation, postmortems list, and postmortem-detail screenshots; no EN/FR-specific layout breaks were found beyond D1/D2 above, which reproduce identically across languages and themes.
