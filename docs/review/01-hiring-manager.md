# Review 01 — DevOps Hiring Manager

**Reviewer lens:** Would I pull Jean-Michel in for a DevOps / Platform / SRE interview based on this site alone?

**Short answer: yes, with reservations.** The `/postmortems` and `/updates` content is the strongest evidence I've seen on a personal site in this category — real root-cause chains, upstream bug tracking, RBAC verification commands, specific metrics. The site's own operational hygiene (security headers, a flagged critical `npm audit` vuln, a `next start`/`output: standalone` misconfiguration) undercuts that story on the one surface where the candidate controls everything end-to-end. The `/about` page gives me none of the conventional signal (years of experience, employer names, seniority) I'd use to screen before reading further — I have to go dig in `/postmortems` myself to form that judgment, which a time-pressed hiring manager won't always do.

## Top 5 strongest pieces of content (ranked)

1. **Longhorn instance-manager memory leak postmortem** — `content/postmortems/2026-07-31-longhorn-instance-manager-leak.md`. Clean root-cause chain (170MB/day leak traced to a 430-snapshot pileup inherited from an earlier incident) with a follow-up section 54 days later showing the same alert firing again, this time correctly distinguished from a genuine upstream Longhorn gRPC leak (links to `longhorn/longhorn#12643`, `#12668`, `#12573`) and a correct understanding of why a naive version-bump doesn't actually move the leaky process. This is the single best piece of evidence on the site that he can read a metric, trace it to a specific prior change, and tell a false recurrence from a real new bug.
2. **Scoping ServiceAccounts off cluster-admin** — `content/updates/2026-09-13-scoping-serviceaccounts-off-cluster-admin.md`. Found by accident during a token rotation, but handled like a real security engineer would: deletes-and-recreates the SA to invalidate a leaked token immediately, writes a minimal `ClusterRole` instead of leaving `cluster-admin`, and *verifies* with `kubectl auth can-i` rather than assuming the YAML did what it says.
3. **Live infrastructure dashboard** — `/infrastructure` (`src/components/InfrastructureContent.tsx`). Not a screenshot or a static diagram — it's a real-time view into the actual cluster (node online/offline state, pod counts, which node is currently serving traffic, a rotate-pod control), which is a stronger signal of operating a system than describing one.
4. **Homelab shutdown cascade postmortem** — `content/postmortems/2026-08-31-homelab-shutdown-cascade-nic-swap-docker-down-and-stale-port-forwards.md`. Seven independently-diagnosed, stacked root causes (compose-down vs. stop, Docker embedded-DNS fallback race, stale systemd unit colliding with a container, hardcoded LAN IPs in three files, who actually owns NAT) resolved in one incident — shows breadth across Docker, DNS, DHCP, and network ownership boundaries.
5. **Homelab documentation (`/documentation`)** — `src/data/homelab.ts`. Dense, specific operational knowledge that reads like real runbook material, not marketing copy — e.g. the k3s control-plane entry describing a sqlite datastore bloating from lease/CRD revision churn, pegging CPU near 100%, fixed by retention-pruning for a ~15x reduction in both DB size and CPU load.
